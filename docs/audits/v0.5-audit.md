# v0.5 post-implementation audit

- **Date:** 2026-10-15
- **Audited code:** `main @ b25e0a99` (all v0.5 implementation issues #90–#97 merged) plus the audit fix commit `3f14b987` (PR #124)
- **Audit issue:** #102
- **Method:** full repository read (CLI, config, workspace, run, resume, runner, orchestrator, all pipeline stages, renderers, review, TUI, docs, Makefile, CI, schemas, tests), requirement matrix against #98's release criteria and user journey, quality-gate and E2E execution, gosec gate-integrity review.
- **Validation run:** `make check` (fmt, vet, tests, coverage, golangci-lint, gosec, build) and the v0.5 offline E2E suites, all executed under Go 1.27.2 on macOS.

## Executive summary

The repository **does satisfy the complete v0.5 product and engineering expectations**. Every one of the ten release criteria in #98 passed against real code and tests (no PASS was inferred from names or comments). The operator journey — configure once, start a run, research → verify → bounded follow-up → write → final factual check → render, persist everything, review, resume/retry — works from a MacBook with remote oMLX/SearXNG, and every `PASS` below is backed by an offline test that exercises real code paths.

The audit found **five** concrete defects. Four were fixed inside the release workstream (PR #124) because they directly affected definition-of-done items ("real operator documentation", "output correctness", "quality gates"); one low-severity consistency gap is tracked as issue #125. The most important finding was that the **security gate was hollow**: `make security` swallowed all gosec failures, and the pinned gosec release's x/tools loader could not read Go 1.27 build caches, so the new taint-analysis engine silently skipped every package. The gate is now strict, exclusion-free, and proven to fail on a reintroduced vuln.

## Release recommendation

# READY WITH NON-BLOCKING GAPS

All release criteria pass and all definition-of-done boxes are verifiable. One low-severity consistency gap remains open ([#125](https://github.com/Mundo-Dolphins/local-newsroom/issues/125) — resumed writer derives its artifact type from the current config while render uses the recorded snapshot); it is safe (outputs stay valid, secret-safe, and match the recorded format) and requires a deliberate semantics decision, so it does not block the release.

## Audit dimensions (per #102)

### 1. Functional completeness — PASS

All ten criteria above; no MISSING/BROKEN/NOT TESTED requirement. The one NOT-TESTED-behavior found (resume after a config format change) is tracked as #125, not a missing feature.

### 2. Architecture consistency — PASS

- TUI duplicates no pipeline logic (presentation over `Service`; new/resume/retry all call the shared `planRun`).
- CLI composes the same services as the TUI; `run_plan.go` is the only place run construction exists.
- Persistence (`workspace`) is separated from orchestration (`runner`/`orchestrator`); resume logic (`internal/resume`) is service-agnostic.
- Provider details (oMLX/SearXNG) live in `internal/llm`/`internal/search/searxng` adapters behind the contracts in `internal/contracts`; domain packages take interfaces.
- Profiles inject writing style into the writer only; they cannot disable or weaken the final factual check (separate stage, separate service).
- Renderers are pure functions of the artifact (no LLM, deterministic order/length); final checking is an independent stage with its own artifact.

### 3. Persistence and resumability — PASS (one low gap → #125)

Every stage persists its artifact; the manifest updates on every state transition (runner persists each stage state change; verified by the SIGINT E2E, where a killed run leaves a `cancelled` manifest with complete attempt history). Resume skips succeeded stages, retry invalidates transitive downstream, stale artifacts are integrity-checked (hash regression check) and corrupt runs fail safe (fail-closed checks in `internal/resume`). One consistency gap: the resumed writer's artifact type comes from the current config while `runRender` uses the snapshot — #125 (low).

### 4. Configuration — PASS (docs fixed in PR #124)

Precedence CLI > env > file > defaults verified by `TestE2E_v05_ConfigPrecedence`; endpoints, models, workspace, archive, profile roots, search, embedding/rerank all resolve through one mechanism. Secrets: config file rejects literal secret values (env-reference only), `SecretValues()` feeds the workspace `Sanitizer`, and resolved values are redacted in `config show` output and run manifests. The documented lookup order was wrong in three files (wrong order, wrong XDG path, missing dot, missing `NEWSROOM_CONFIG`) — corrected in PR #124 to match `config.DefaultLocations()`.

### 5. Editorial safety — PASS

Researcher claims are source-traceable (claim IDs → source document IDs); the verifier covers every claim and reports honest `verified|unsupported|contradicted|needs_review` states; the writer consumes only the verification result (unsupported claims cannot silently become assertions); claim IDs remain traceable in the artifact and are validated by the final checker; the final checker blocks output on any factual failure (double gate, dimension 8). Names/dates/statistics/quotes: the writer prompt is constrained to the dossier+verification record and the final checker re-verifies claim-level support — mutation would surface as a check failure. Bluesky rendering: deterministic packing, and (post #124) the 300-character budget is absolute even with claim references; non-fitting content fails with `IndivisibleSegmentError` instead of truncating facts.

### 6. Output correctness — PASS (renderer fixed in PR #124)

Article output renders title/sections/body from the artifact (readable markdown, `TestE2E_v05_ArticleRunSucceeds` + renderer tests). Bluesky: every rendered post ≤ 300 chars in the E2E thread run; the latent over-budget path (claim-reference suffix added after a budget check that didn't include it) was reproduced (324-char post) and fixed by reserving the suffix budget in every packing decision. Final output is marked usable only after final-check pass (`ready` in the review bundle is computed exclusively from `succeeded` + `final_check=pass` + output present). Review bundle accurately reflects status/warnings (94.3% coverage in `internal/review`; readiness logic verified). Artifact paths are valid and reloadable (`TestE2E_v05_ArtifactsSurviveReload`).

### 7. Operator usability — PASS

Help text on every command; sensible defaults (workspace `.newsroom`, 80%/600ms-safe defaults documented); useful errors (resume of a non-existent/active run, format errors with the valid set, config errors naming the offending key); progress visibility in both CLI (per-stage lines) and TUI (live stage bar, endpoint header); recent-run discovery (`newsroom run --list`, TUI run list); resume/retry discoverable from the failed-run summary and TUI keys; final artifacts listed in the run summary and openable from the TUI. Docs: `docs/first-usable-workflow.md` is an executable 8-step operator guide; its inaccuracies were found in this audit and fixed in PR #124. No remaining gap materially affects first usability.

### 8. Test coverage quality — PASS

Total coverage 82.0% (floor 80%). Important behaviors are tested, not just counted: happy path, partial failure (final-check failure E2E), interrupted run (real-binary SIGINT), retry + downstream invalidation (attempt-count assertions), config precedence, secret redaction (`TestE2E_v05_NoSecretsInWorkspace`), article/Bluesky output, persistence reload, and the v0.2–v0.4 E2E suites (backward compatibility). Per-package coverage of v0.1–v0.4 packages (`retrieval` 54.7%, `verifier` 62.2%, `workflow` 56.1%, `runner` 78.6%, `types` 16.7%) is below 80% individually, but the repository convention is a single repository-wide floor and the behaviors of those packages are covered end-to-end; recorded as an intentional limitation, not a gap.

### 9. Documentation vs implementation — PASS (fixed in PR #124)

Verified executable: config section, research/write/final-check/archive commands, run, review, TUI, `make` targets. Discrepancies found and fixed: config lookup order (README, operator guide, example YAML header), `output_format` enum comment (`article | thread | hybrid`, not `social | summary`). TUI keymap in README/docs matches `internal/tui` (`j/k enter n r t c o v ? q`). Review flags (`--workspace-root`, `--no-save`) match `review_cmd.go`.

## Intentional limitations (in scope, not gaps)

- **No publication**: nothing publishes anywhere (Bluesky/Hugo/Git). v0.5 stops at ready artifacts + human review. Auto-publish is v0.6 by design.
- **Single-user, local-first**: one operator, local workspace; no server/multi-user mode (v0.6+ explicitly deferred).
- **Claim references off by default** in thread rendering (operator opt-in); when on, the 300-char budget is absolute (post-#124).
- **Profiles cannot disable the final factual check** — this is the editorial-safety guarantee, not a limitation.
- **Remote endpoints via base URL only**: oMLX (Mac Studio) and SearXNG (Pi) are addressed as OpenAI-compatible/SearXNG-compatible HTTP endpoints; no auth beyond API keys, which never leave the environment.
- **Repository-wide (not per-package) coverage floor** — the long-standing repository convention; v0.1–v0.4 packages below 80% individually are covered end-to-end by the E2E suites.
